## 实测数据

### SDK 路径(普通钱包 + 普通 source URL)

走通 4 关:`node4.gonka.ai` 不是 chain-api 入口 → `node3.gonka.ai` 才是 → `random.choice` 选中已迁移的旧 entry → 手动锁 `GONKA_ENDPOINTS` + 加 `/v1` → 最后 **403 `Transfer Agent not allowed`**。

链上 `allowed_transfer_addresses` 只有 **7 个治理批准的 transfer agent 地址**,自派生的地址不在内。所有 SDK 直连请求都被卡在签名鉴权这一步。

### Router + Kimi (4 种失败 mode)

| 配置                                          | 结果                          | 备注 |
| --------------------------------------------- | ----------------------------- | ---- |
| 干净 streaming                                | `winner stalled 1m30s`        | 昨天的失败 |
| 干净 streaming(今天复测)                    | `peer closed connection` ~90s | 同因不同表象 |
| 干净 streaming + 长跑                         | `502 Bad Gateway`             | 同因 |
| `chat_template_kwargs.enable_thinking=true`   | `500 do_request_failed`       | new-api 拒收自定义字段 |

4 ticker 并发完整 default 配置(`-j 4 NVDA AAPL MSFT GOOGL`):**1/4 成功,50m6s 总耗时**。AAPL ✅ Underweight(单 ticker 跑了 50 分钟,中间过 502 重试),其余 3 个全 `peer closed connection`。对比 Qwen3 同配置 13m57s / 4-of-4。

## 关键发现

- **Router 是 `new-api` 网关,不是薄代理**(500 错误码 `do_request_failed` 是 new-api 错误码,字段会被规范化)。所以 vLLM 私有扩展(`chat_template_kwargs.*` 等)**全部过不去 router**——客户端没有任何字段能开 reasoning streaming。
- **SDK 路径的存在意义不是"简化",是"代付层"**:`allowed_transfer_addresses` 是治理参数,7 个地址被授权代付推理费;router 后台持有这些白名单私钥,通过 `sk-...` bearer 做用户记账。所以 SDK 不是"私钥够了就能用",普通用户走不到。
- **Kimi K2.6 实际已经在 Gonka 主网**(`https://node4.gonka.ai/v1/models` 返回 Qwen3-235B + Kimi-K2.6,55 个 participant 里 23 个声明支持 Kimi)——**昨天日报里的"Kimi 没上 Gonka"结论作废**。但因为白名单 + router 不转发 reasoning streaming 字段,**普通用户跑 Kimi 仍然不可行**。

## 没解决 / 未来方向

- **生产保持 Qwen3 走 router**——可靠率 100%,~14 min / 4 ticker。Kimi 走任一路径都不可行。
- **SDK 路径解锁**前提:Gonka 治理放开 `allowed_transfer_addresses` 白名单或 onboarding 流程。本仓库代码侧准备就绪(`GonkaClient._build_sdk_llm` 跑到鉴权前都对),等链上变化。
- **多 TA fan-out** 暂时阻塞——前置依赖 SDK 路径可用。
- **LangGraph 节点级并行**(4 analyst 互不依赖,可并行)不依赖任何外部状态,是接下来纯客户端就能做的优化。

## 演示讲点

1. 今天试了两条逃出 router 限制的路:SDK 直连、给 router 加 `enable_thinking` 字段。**两条路都被堵**,原因都比预想深。
2. SDK 直连失败链路 4 关的复盘——尤其是最后白名单这关,揭示 router 不是"代理"而是"代付层"。
3. Router 是 `new-api` 网关的发现 + 它会规范化字段的影响:任何 vLLM 私有扩展都过不去。
4. **Kimi 已经在 Gonka 主网上线了**(纠正昨天的判断),但对普通用户仍然不可用。
5. 生产路径定下来:**Qwen3 + router**,新方向投资在 LangGraph 节点并行而不是继续折腾 Kimi。
