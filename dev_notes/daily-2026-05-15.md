1. **分析 SDK 路径修复**(commit `93a593b`):用 `GET {source}/v1/identity` 拿网关白名单地址做 transfer agent,自己的私钥负责签名 + 付费。昨天判定"白名单门槛"的结论作废,SDK 路径对普通用户可用。

3. **Dashboard 升级多页**(`st.navigation`):Decisions / Tasks / Settings 三页。Tasks 页用 detached subprocess + `start_new_session` 异步跑任务,日志末 30 行可展开,Stop 按钮 `killpg(SIGTERM)`。Settings 页存 `~/.tradingagents/app/settings.json`,切换 Router/SDK 时保留另一种的凭据。
4. **修了 zombie 检测 bug**:子进程退出后变 zombie,`os.kill(pid, 0)` 仍返回成功,任务永远显示 running。改成模块级 `Popen` 句柄字典 + `.poll()` 主动 reap,fallback 读 `/proc/<pid>/status` 处理 dashboard 重启后的旧 PID。

## 关键发现

- **SDK 双身份模型**:Signer / Payer 是用户私钥(扣 GNK),Transfer Agent 是网关身份(满足链上白名单)。之前把两件事混成一件 → 自派生地址不在白名单 → 403。修复后两件事拆开 → 普通用户可用。
- **SDK 路径反而比 router 快**:直连 `node4.gonka.ai`,省掉 `api.gonkascan.com` + new-api 网关 + Cloudflare 这层代理。但同样跑在 CF 后面,**100s 超时仍存在**。
- **新错误码**:`winner inference incomplete (nonce_finished=false)` —— Gonka PoC 2.0 流程内部的 executor 异常,客户端无法控制,只能靠 SDK 自动重试。
- **Streamlit 多页 + 异步 subprocess** 体验比之前阻塞 UI 的"Run now"按钮好得多;但要小心 zombie 进程问题(已修)。

## 没解决 / 未来方向

- **多 TA fan-out 仍未实现**——SDK 现在固定打一个 gateway,要真正"用满 Gonka"需要做客户端层 round-robin。
- **`winner inference incomplete` 这类 Gonka 内部错误**没法在客户端解决,只能等节点行为更稳定。
- **Dashboard 鉴权**——目前任何能访问端口的人都可改 settings、看私钥。生产部署需要前置一层 auth。
- **LangGraph 节点内并行** 没动过。
